# NumPy 2.1.x Upgrade Implementation Plan

> **Historical.** Implemented. Line citations into `petbox/dca/primary.py` have since
> shifted, and the `np.bool_` occurrence this document targets already reads `bool`. Test
> counts quoted here predate later work.

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Update petbox-dca to require numpy >= 2.1 and scipy >= 1.13, dropping Python < 3.10 support.

**Architecture:** This is a dependency bump with a small number of deprecation fixes. NumPy 2.0 introduced ABI-breaking changes that require scipy >= 1.13. NumPy 2.1 requires Python >= 3.10. The codebase is already nearly compatible — only two deprecation items need fixing (`np.bool_` → `np.bool` and `RandomState` → `Generator`).

**Tech Stack:** numpy >= 2.1, scipy >= 1.13, Python >= 3.10

### Task 3: Migrate RandomState to Generator

**Files:**
- Modify: `petbox/dca/base.py:24,53`
- Modify: `petbox/dca/primary.py` (all `naive_gen` lambdas)
- Modify: `petbox/dca/associated.py` (all `naive_gen` lambdas)
- Modify: `test/test_dca.py` (any RandomState usage)

This is the most involved change. `ParamDesc.naive_gen` is typed as
`Callable[[RandomState, int], NDFloat]` and every model's
`get_param_descs()` provides lambdas like `lambda r, n: r.uniform(...)`.
The `Generator` API is compatible for these methods (`uniform`, `full`,
`zeros`), but the type signature changes.

- [ ] **Step 1: Check test usage of RandomState**

Search `test/test_dca.py` for `RandomState` or `random` to understand
how `naive_gen` is called.

- [ ] **Step 2: Update ParamDesc type in base.py**

```python
# Before
from numpy.random import RandomState

...
naive_gen: Callable[[RandomState, int], NDFloat]

# After
from numpy.random import Generator

...
naive_gen: Callable[[Generator, int], NDFloat]
```

- [ ] **Step 3: Update test code**

Any test that creates a `RandomState` and passes it to `naive_gen`
must switch to `np.random.default_rng(seed)`.

The `Generator` API methods `uniform`, `normal`, etc. have the same
signature as `RandomState` for the patterns used here, so the lambdas
in `get_param_descs()` should not need changes.

**Key difference:** `Generator.uniform(low, high, size)` works the same
as `RandomState.uniform(low, high, size)`. No lambda changes needed.

- [ ] **Step 4: Run tests**

Run: `pytest -q`
Expected: All 27 tests pass

- [ ] **Step 5: Run mypy**

Run: `mypy petbox/dca`
Expected: No issues

- [ ] **Step 6: Commit**

```bash
git add petbox/dca/base.py petbox/dca/primary.py petbox/dca/associated.py test/test_dca.py
git commit -m "refactor: migrate RandomState to Generator for numpy 2.x"
```

## Risk Assessment

| Risk | Mitigation |
|------|-----------|
| `RandomState` → `Generator` breaks downstream users who pass `RandomState` to `naive_gen` | `naive_gen` is an internal field of `ParamDesc`, not part of the public API. Only used in test suites. |
| numpy 2.1 floor excludes Python 3.8/3.9 users | Python 3.9 EOL was Oct 2025. Python 3.10+ is reasonable for new releases. |
| scipy 1.13 floor is aggressive | scipy 1.13 was released April 2024 — nearly 2 years ago. Pip will resolve. |

## Notes

- `np.float64`, `np.intp`, `NDArray`, `np.putmask`, `cumulative_trapezoid`, `expi`, `gammainc` — all verified stable in numpy 2.x
- `np.bool_` still works in numpy 2.x but is deprecated; will be removed in numpy 3.0
- `RandomState` still works in numpy 2.x but `Generator` is the recommended replacement
- No scipy API changes affect this codebase — only the ABI compatibility floor matters
